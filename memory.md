## Durable notes

- Preserve custom authorization architecture and last-administrator safeguards.
- Adding a **platform** permission touches four places: `App\Enums\PermissionSlug` case, `AuthorizationSeeder` (display-name map **and** the `$platformAdminPermissionSlugs` allow-list), the hard-coded counts in `tests/Feature/Authorization/AuthorizationCatalogueTest.php`, and the catalogue table in `docs/authorization.md`. Adding a **company-scoped** permission touches only `App\Enums\CompanyMemberRole::permissions()`. Keep the two namespaces' slugs distinct (`analytics.view` vs `platform_analytics.view`).
- Keep route permission middleware and Policy checks authoritative on the server. Navigation visibility is presentation only.
- **Never hold mutable state on a service or controller.** Laravel caches the resolved controller — and therefore its injected services — on the `Route` object, so a memoised value is served stale on the next read. Compute aggregates per call.
- **MySQL/InnoDB owns foreign key backing indexes.** It silently drops a redundant FK index when a covering index is added, and refuses to drop an index a FK depends on. Guard every index DDL in a migration with `Schema::hasIndex()` and make `up()`/`down()` idempotent; restore FK backing indexes before removing composites. Verify migrations on MySQL, not only on the SQLite test suite.
- `AuditLogService::sanitizeValue()` now accepts `null` metadata values. Keep `resources/js/types/audit-log.ts` in sync with the PHP enums.
- Rebuild frontend assets (`npm run build`) after modifying controller actions or route definitions used by Wayfinder.
- Feature 6–9 deferred delete protections active via `restrictOnDelete` FKs on `job_postings`.
- Company members scoped per company; never grant platform-admin permissions.
- Report moderation never auto-removes content; actual removal goes through job moderation (`jobs.moderate`) / employer suspension (`employers.manage`).
- Audit trail (Feature 31): append-only, admin-only, no write routes; audit writes inside business transactions are fail-closed, while auth events and read-path writes are fail-soft.
- **Experience-level band comparison uses a unique band rank** derived from `(sort_order, id)`, never raw `sort_order`. Distinct levels must never compare as the same band.
- **The skill index is synced from the `created` and `updated` model events**, not `saved` (Laravel never records changed attributes on insert).
- `location_city` is derived by an `Attribute` mutator on `location` and is **not** mass-assignable.
- **The candidate preference columns carry no database-level foreign key** (SQLite refuses to drop a FK-participating column). Validated with `exists:`; dangling degrades to "no preference".
- **Endpoints that return no Inertia page (e.g. `204 No Content`) must never be called via the Inertia router** — Inertia then renders its built-in `inertia-error-dialog`. Call them with axios via `resources/js/lib/http.ts`. This is enforced by `AGENTS.md` rule 10.
- **Complex `hasOne ... ->ofMany('id','max')` eager loads need qualified select columns** (`conversation_messages.id`, …) — an unqualified select on a table that is both outer and in the `ofMany` subquery raises `ambiguous column name`.
- **Broadcast events after commit, never inside `DB::transaction()`**; queue dispatch uses `ShouldBroadcast`; tests use `Event::fake()` + `BroadcastFake` equivalents (`BROADCAST_CONNECTION=null`, `QUEUE_CONNECTION=sync` under phpunit).
- **Notification payloads are name + job title + URL only, never message bodies**; at most one unread message notification per conversation per recipient (coalesced).
- **axios only for non-Inertia async XHRs**: shared instance in `resources/js/lib/http.ts` (sends `XSRF-TOKEN` cookie as `X-XSRF-TOKEN` automatically; same-origin cookies are automatic). Inertia router stays authoritative for page visits; no axios re-fetch of page data after mount. Raw `fetch`/`XMLHttpRequest` are banned by convention.
- **Messaging scale: no global `messages_unread_count` shared prop** (it scanned all conversations on every request); unread totals are an `unread_total` prop on the inbox only, computed via two index-driven branches. Inbox uses a UNION (candidate/employer branches) ordered by a denormalized indexed `application_conversations.sort_at` (migration `2026_11_16_000001_add_conversation_sort_at`); thread history is keyset (`before` cursor). See spec D12; bench evidence on a throwaway DB measured sub-millisecond per-user query times on ~300k messages.
- Never store `.env` values, credentials, tokens, private keys, or personal data here — Reverb credentials stay in `.env` (gitignored).
- `memory.md` is a formatted file: `npm run check` (prettier via vp) checks it in CI, so always run `npx vp check --fix memory.md` after editing it by hand, before committing.
